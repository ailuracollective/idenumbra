# idenumbra-bol

Bolivia identification validator.

## Documents

- CI (identity card, 5-8 digits plus an optional 1-2 character complement).
- NIT (tax number, 9-11 digits).

## Validation algorithm

CI: 5-8 digits; the complement (when present) is 1-2 ASCII alphanumerics,
optionally after `-` or a space (the two-letter departmental extension, e.g.
`LP`, `SC`, is not checked). NIT: 9-11 digits, and the third-from-last digit
must be `0` followed by a documented control code (`01`, `02`, `04`; `03` also
appears in the SIN's own supplier lists). All-zero placeholders are rejected;
everything else is structure only.

No check digit exists for either document:

- The CI is the registry number the SEGIP assigns; the SEGIP publishes no
  verifier algorithm.
- The NIT's last three digits are control codes, not a check digit. Per the SIN,
  a natural person or unipersonal company gets the CI followed by `01` and one
  random digit, legal persons get `02`, foreign persons `04`; the remaining
  control digits are generated by the SIN's system. The SIAT "Módulo 11" page
  computes the CUF (invoice code) and is explicit that its input includes the
  NIT — it is not a NIT checksum.
- Cross-check: the SIN's own supplier lists (2022-2026; 1,112 values of 9-11
  digits) all end in `0` plus a control code except one 2024 row that repeats a
  company's 2025 NIT with an extra digit. The control code is `01` or `02` in all
  but five rows (code `03`), and the final digit runs 0-9, so the SIAT "1 al 9"
  wording is not enforced. Seven-digit values in those lists are CIs, not NITs.

### Editable constants

- `NIT_MIN_LEN = 9` / `NIT_MAX_LEN = 11` (`src/validators/nit.rs`) — the SIN
  publishes no bound; 9-11 are the lengths its own supplier lists. Edit when the
  SIN documents a range.
- `NIT_CONTROL_CODES = [1, 2, 3, 4]` (`src/validators/nit.rs`) — `01` natural
  person/unipersonal, `02` legal person, `04` foreign person per the SIAT page;
  `03` was added because it appears in the SIN supplier lists. Edit when the SIN
  publishes a new code.

## References

Official sources are listed first; the `implementation` ones are the cross-checks used where the agency does not publish the check-digit algorithm.

- **Official** — SIN/SIAT, *Generación del NIT* (natural person born in Bolivia
  and unipersonal company: NIT = CI + code `01` + "un número aleatorio del 1 al
  9"; legal persons: the last three digits "incluyen el código `02`" + a random
  digit; foreign natural person with foreigner CI: code `04`):
  https://siatanexo.impuestos.gob.bo/index.php/requisitos-para-la-inscripcion/conceptos-generales/generacion-del-nit
  — checked 2026-11-17. The page publishes neither a length range nor codes
  `03`/`00`, and says the random digit starts at 1.
- **Official** — SIN/SIAT, *Algoritmo Módulo 11* (the autoverifier of the CUF;
  its input string includes the NIT, it is not a NIT checksum):
  https://siatinfo.impuestos.gob.bo/index.php/facturacion-en-linea/algoritmos-utilizados/algoritmo-modulo-11
- **Official** — SEGIP, *Cédula de Identidad* (requirements only; no numbering
  or check-digit rule is published):
  https://www.segip.gob.bo/index.php/servicios/cedula-de-identidad
- **Cross-check** — CIAT 2014, Bolivia country report (natural persons and
  unipersonals: NIT = CI + three control codes assigned by the administration;
  legal persons: control codes generated by the system):
  https://www.ciat.org/Biblioteca/AsambleasGenerales/2014/Espanol/2014_tema3.2_Arinez_Bolivia.pdf
- **Cross-check** — SIN, *Nóminas de proveedores* (the agency's own supplier
  lists, 2022-2026; 1.1k NITs used for the length range, the `0` position and
  the control codes, including the `03` rows):
  https://www.impuestos.gob.bo/index.php/proveedores/
- **Cross-check** — python-stdnum, *Add support for Bolivia TIN* (discussion and
  public NIT samples): https://github.com/arthurdejong/python-stdnum/issues/134
- **Cross-check** — org-id.guide, BO-NIT (format examples):
  https://org-id.guide/list/BO-NIT

An earlier version of this crate applied the SIAT CUF modulo 11 to the NIT; the
public NIT samples in the python-stdnum issue do not validate with it, so the
check was removed. Use the SIN "Verifica NIT" service for existence.

Official links checked on 2026-11-17, as were the SIN supplier lists; the
cross-checks are public implementations/data, not the rule source.

## Usage

All features:
```toml
[dependencies]
idenumbra = { version = "0.1.0-alpha.1", features = ["all"] }
```

Single feature (only the country you need):
```toml
[dependencies]
idenumbra = { version = "0.1.0-alpha.1", features = ["bol"] }
```

```rust
use idenumbra::Idenumbra;
Idenumbra::infer("BOL", "12345678")?;
```

## Notes

- Feature flag: `bol`.
- Country code (ISO 3166-1 alpha-3): `BOL`.
- Lazy loading: only compiled when the corresponding Cargo feature is enabled.
- A number of 9 or more digits is treated as a NIT; a NIT only passes when its
  third-from-last digit is `0` and the next one is a control code (`01`, `02`,
  `03`, `04`). A 5-8 digit number is a CI.
